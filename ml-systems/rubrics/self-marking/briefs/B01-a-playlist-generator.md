# B.1 A playlist generator

*Unworked brief · decided on **Objective** · Appendix B*

A music service builds a thirty-track playlist from one seed, for a listener who hears it in order.

Mark the deciding row first. Then score every row below, at or above the bar against the anchor given, and write the minute the artefact appeared.

| Row | Above the bar on this brief | Band | Minute |
|---|---|---|---|
| **Objective** (decides) | A sequence, not a set; completion as a proxy and skips as evidence; the artist limit as a slot rule; the sponsored slot as a guardrail with its own measurement. | | |
| **Bound** | 60M tracks, 100M listeners, 5M playlists a day; first track in a second; a fifth of listeners with under ten plays; compute nothing. | | |
| **Binds** | Freshness of the catalogue and of the session; not cost. | | |
| **Choose** | A retrieval of candidates then a sequencer; a cold-start path from the seed alone; the offline twist as a precomputed playlist. | | |
| **Deepen** | The skip loop: does the rest of the list change, how fast, and what the label then measures. | | |
| **Close the loop** | What is played is what is learned; the sponsored slot measured separately; new-release freshness as the silent failure. | | |
| **Recovery** | The offline twist answered by moving the build before the listener leaves the network. | | |

**Numbers the marker should expect to hear:** 5M/day; 30 tracks; 3 per artist per 20; a fifth cold listeners.

**Red flags particular to this brief:** treating the playlist as a set; the artist limit as a penalty.
